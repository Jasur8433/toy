# Campus Pass

Сервис для учёта проходов студентов. Он получает события с терминалов Hikvision, сопоставляет поле `employeeNo` (или `cardNo`) со студентом из HEMIS и показывает журнал в веб-панели. Биометрические шаблоны и фотографии **не** принимаются, не хранятся и не передаются: регистрацию лица продолжайте выполнять в iVMS-4200 AC.

## Перед запуском

1. Создайте отдельную сервисную учётную запись на каждом терминале Hikvision с минимальными правами чтения событий ISAPI.
2. В iVMS укажите в `Employee No.` идентификатор студента из HEMIS. Это обязательный ключ сопоставления; ФИО не используется как ключ.
3. Получите у администратора HEMIS URL документированного API студентов, метод авторизации, срок действия токена и названия полей ID, ФИО, группы и статуса.
4. Скопируйте `.env.example` в `.env`, заполните значения и ограничьте доступ к этому файлу: `chmod 600 .env`.

## Запуск

```bash
cp .env.example .env
npm start
```

Откройте `http://127.0.0.1:3000`. Данные журнала сохраняются локально в `data/events.json`; добавьте эту папку в резервное копирование с шифрованием. По умолчанию фоновые задачи запускаются только если заданы соответствующие переменные окружения.

## Проверка интеграций

Все административные запросы требуют заголовок `Authorization: Bearer $APP_ADMIN_TOKEN`.

```bash
curl -H "Authorization: Bearer $APP_ADMIN_TOKEN" http://127.0.0.1:3000/api/health
curl -X POST -H "Authorization: Bearer $APP_ADMIN_TOKEN" http://127.0.0.1:3000/api/sync/hemis
curl -X POST -H "Authorization: Bearer $APP_ADMIN_TOKEN" http://127.0.0.1:3000/api/poll/hikvision
```

`GET /api/events` возвращает только нужные журналу данные: время, направление, терминал, ID студента и статус сопоставления. Студент с неизвестным ID попадает в журнал как `Неизвестный студент`; его нельзя автоматически пропустить или создать в HEMIS.

## Автозапуск 24/7

Измените пути и пользователя в `systemd/campus-pass.service`, затем:

```bash
sudo cp systemd/campus-pass.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now campus-pass
sudo systemctl status campus-pass
```

## Что нужно предоставить для production-подключения

Не передавайте пароли в чат или Git. Нужны: IP/HTTPS-адреса и модели терминалов, включённый ISAPI, тестовая сервисная учётная запись, протокол/схема сетевой изоляции, а также официальная спецификация HEMIS API с тестовым токеном. Перед включением обязательно согласуйте срок хранения журнала, основания для обработки биометрии и права доступа с ответственным за персональные данные института.
